# LifeKeeper（生活管家）

一个**纯前端、本地优先、隐私优先**的个人生活管理网页应用：钱花在哪、日子怎么过、东西放哪、密码是什么，LifeKeeper 帮你记着。

全部数据只保存在**你自己浏览器的本机存储**里，不依赖服务器、不需要注册账号、不发起任何网络请求。

### 视觉与交互

- 严格遵循根目录 `DESIGN.md`（Notion 暖色浅色风格）：配色、字号、间距、圆角、阴影全部取自其中定义的 Token，未自创任何 Token。
- 原生 SVG 图表（donut / 分组柱状图），无图表库；图表含 `<title>`/`<desc>`/`role="img"` 可访问性标注。
- 过渡动画统一 150–200ms ease；`prefers-reduced-motion` 下取消位移动画。
- 当前版本**仅桌面端**（≥1024px 布局）；平板/手机断点与深色模式列入后续 Backlog。

## 运行方式

### 必须通过 Live Server 访问

1. 用 VSCode 打开本目录（工作区根目录即本文件所在目录）。
2. 在资源管理器中右键 `index.html` → **Open with Live Server**。
3. 浏览器会打开 `http://127.0.0.1:5500`（端口以 Live Server 实际输出为准）。

推荐安装的 VSCode 插件：**Live Server**、ESLint、Tailwind CSS IntelliSense、Emmet。

### ⚠️ 禁止直接双击 index.html（`file://`）

**原因**：LifeKeeper 的加密功能依赖浏览器原生 **Web Crypto API**（`crypto.subtle`），而该 API **只在“安全上下文”中可用**。`http://127.0.0.1` 与 `https://` 属于安全上下文，`file://` **不是**。

用 `file://` 打开时，应用会检测到 `crypto.subtle` 不可用，直接显示「需要通过 Live Server 访问」的阻断提示，不会进入应用——这样设计是为了避免在无法加密的环境里写入数据。此外 `file://` 下浏览器通常会拒绝加载 ES Module 脚本。

## 安全说明

### 加密方式

- **密钥派生**：PBKDF2-SHA256，迭代 **210000** 次，从主密码 + 16 字节随机盐派生 **AES-GCM-256** 密钥；派生出的 `CryptoKey` 标记为 **non-extractable**（无法被导出）。
- **加密算法**：AES-GCM，每次加密使用新的随机 **12 字节 IV**；密文统一以 `{ "iv": "<base64>", "ct": "<base64>" }` 结构存储。
- **加密范围**：密码保管模块的**密码字段与备注字段**。其余数据（收支、日记、物品、账号名等）为普通文本，仅在锁定态下不可见。
- **主密码校验**：用派生密钥加密一段固定常量作为校验值（`verifier`），解锁时解密比对；`salt` 与 `verifier` 都不是秘密，可明文存储。

### ⚠️ 忘记主密码不可恢复

LifeKeeper **不提供“找回密码”功能**，这是设计选择而非缺陷：

- 主密码不会被保存在任何地方，只在你输入时用于派生密钥；
- 没有服务端、没有邮箱/手机号可以验证身份；
- 因此**一旦忘记主密码，已加密的数据（密码与备注）在数学上无法恢复**。

忘记主密码时唯一的选择是「清空数据重新开始」——这会删除本机全部数据。**请务必牢记主密码，并定期导出加密备份。**

### 数据存储位置

| 内容 | 位置 |
|---|---|
| 业务数据（收支/日记/物品/账号） | 浏览器 `localStorage` 的键 `life-keeper:db:v1` |
| 写作草稿 | 浏览器 `localStorage` 的键 `life-keeper:draft:diary`（独立命名空间，不属于业务数据库、不进备份） |
| 会话密钥 | **仅内存**（`main.js` 的单一模块变量），锁定 / 自动超时 / 关闭页面时立即清除 |

- 锁定或刷新页面后，未解锁状态看不到任何业务数据；
- 存储中**不存在任何明文密码或明文主密码**；
- 应用不含任何统计/追踪/广告脚本，业务数据**不发起任何网络请求**（导出备份是纯本地文件下载）。

### 定期备份建议

- **推荐**：设置 →「数据备份」→ **导出加密备份（推荐）**，把 JSON 文件保存到 U 盘、移动硬盘或你自己的加密云盘。
- 加密备份里的密码与备注仍是密文，**需要用导出时的主密码才能解开**；因此备份与主密码应分开妥善保管。
- **明文备份**会导出可直接阅读的密码，仅在确有必要时使用；导出后请立即转移并删除原文件。
- 换设备或清理浏览器数据前，请先导出备份。
- 建议每次有重要记录后（或至少每月一次）导出一次。

### 已知限制

- 加密范围只覆盖密码保管模块的密码与备注字段，其它模块为普通文本存储；如对整库机密性有更高要求，请等待后续版本。
- 明文导出的密码字段不做掩码处理（这符合 PRD F6-3 的“明文导出”语义，正因如此才需要强警告 + 确认文字）。
- 若导入的备份自带**不同**的主密码凭据，导入后台会立即回到锁定状态，需要改用该备份对应的主密码解锁；此时本机原有凭据已被覆盖。
